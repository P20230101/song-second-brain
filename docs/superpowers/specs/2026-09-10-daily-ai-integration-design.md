# 松的第二大脑：每日 AI 学习闭环集成设计

日期：2026-09-10  
状态：已确认，待实施

## 目标

在现有 Karpathy LLM Wiki 结构上，完成一个可重复的 Obsidian 学习闭环：

1. 用本机 Codex CLI 通过 Claudian 接入 Obsidian；
2. 在一个 Markdown 文件中追加每天与 AI 的原始对话；
3. 用研究上下文模板作为论题/开题报告的唯一分析依据；
4. 让 Codex 按固定规则把每日对话整理为分析结果，并将可复用结论写回 `wiki/`；
5. 保持公开 GitHub Pages 不泄露原始对话；终端插件作为可选工具，不作为核心依赖。

## 方案与取舍

采用“Claudian + Codex CLI + Markdown 工作流”。Claudian 已存在于 Vault，Codex CLI 已安装且可执行，因此不再引入第二套 AI 客户端。终端插件只在 Obsidian 社区插件可直接安装时启用；即使终端不可用，AI 主流程仍可运行。

原始对话写入 Vault 根目录的 `每日对话记录.md`，并加入 Git 忽略，避免公开发布隐私。研究上下文写入 `wiki/研究上下文.md`，由用户填写；模板不伪造论文内容。每日整理结果写入 `wiki/每日学习闭环-YYYY-MM-DD.md`，只有确认可复用的结论才进入其他 Wiki 页面。

## 文件与职责

| 文件 | 作用 | 公开性 |
|---|---|---|
| `wiki/研究上下文.md` | 研究问题、范围、术语、方法、评价标准、当前阶段 | 公开模板，用户可改为公开内容 |
| `每日对话记录.md` | 每日原始对话的追加式单一日志 | 本地私有，Git 忽略 |
| `wiki/每日学习闭环-YYYY-MM-DD.md` | 每日结构化总结、分析、行动和 Wiki 写回记录 | 公开 |
| `AGENTS.md` | 代理必须遵守的读写边界和闭环规则 | 公开 |

## 数据流

```text
Obsidian/Claudian 对话
        │
        ├─ 追加原始内容 → 每日对话记录.md（本地）
        │
        └─ 固定整理提示词 → 读取研究上下文.md + 当日记录
                              │
                              ├─ 输出当日学习闭环页
                              ├─ 提取待验证问题/下一步行动
                              └─ 仅将可复用结论写入 wiki/，更新 index.md、log.md
```

## 固定整理规则

每次整理必须区分“来源事实”“我的推断”“待验证内容”，禁止把猜测写成事实；分析必须引用研究上下文中的目标或问题；未达到可复用标准的内容只留在每日页；写回 Wiki 前检查是否已有同义页面，避免重复节点。

Claudian 当前没有承诺“每次对话自动导出为 Markdown”这一后台能力，因此闭环采用一个固定的一键提示词完成追加与整理。这样不依赖未确认的插件 Hook，也保留人工检查点。

## 终端与 CLI 配置

- Codex 可执行文件：`C:\Users\Administrator\AppData\Local\OpenAI\Codex\bin\fd4c151a749f3ab4\codex.exe`
- Claudian Codex provider：启用，使用上述本机路径。
- Obsidian Terminal：若社区插件安装成功则启用；若安装失败，保留 Claudian 的 Bash/CLI 能力，不阻断主流程。

## 验证标准

1. `codex.exe --version` 返回版本号；
2. Claudian 设置中 Codex provider 为启用且路径可检测；
3. 在 Claudian 中执行一次只读测试，能读取 `AGENTS.md` 并返回其闭环规则；
4. 固定提示词能在 `每日对话记录.md` 追加一条记录，并生成当天学习闭环页；
5. `每日对话记录.md` 不被 Git 跟踪，公开 Pages 不出现原始对话；
6. Wiki 页面之间的相对链接可解析，`index.md` 与 `log.md` 有对应入口和记录。

## 已知限制

- 没有论题/开题报告正文时，分析只能依据模板中的用户填写内容；不会自动臆造研究主题。
- Claudian 官方未提供已确认的“每次对话后台自动导出 Markdown”开关，因此每日记录需要使用固定提示词触发；这属于可重复的一键流程，而不是后台监听器。
- 终端插件是第三方社区插件，安装和维护独立于 Codex 主流程。
