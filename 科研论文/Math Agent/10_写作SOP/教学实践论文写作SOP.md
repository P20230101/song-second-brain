# 教学实践论文写作 SOP

## 适用范围

本流程用于小学 1—3 年级新教材背景下的教学实践类论文，尤其适合教学方式、学习方式、作业设计、课内练习、质量评价等主题。成稿以一个具体课例或一类细小课堂问题为中心，篇幅默认控制在 3 000—5 000 字。

## 一、先收小题目，再查材料

选题不从大概念开始，而从一个可以在一节课中看见的现象开始。

| 不宜直接使用的题目 | 收小后的写法 | 论文真正要回答的问题 |
|---|---|---|
| 新教材下小学数学作业设计研究 | 从“算出6”到“说清6” | 学生会算但说不清过程时，练习怎样设计？ |
| 小学数学分层作业研究 | 同一目标下的三步练习设计 | 不同起点的学生怎样走向同一算理？ |
| 小学数学评价改革研究 | 用一句追问听见学生的思考 | 教师在课内练习中看什么、怎么接？ |

成功标准：题目中必须同时出现**具体内容、具体教学动作、具体研究角度**。题目不宜只写“研究”“探索”“策略”。

## 二、建立写作资料包

资料搜集不是为了把文献综述写得很长，而是为了让教学判断有依据。

| 材料类型 | 最少内容 | 在论文中怎样使用 |
|---|---|---|
| 课标与教材 | 课程标准、教材例题、教师用书 | 解释为什么选这个内容、这一课要求学生理解什么 |
| 课堂材料 | 教案、练习单、板书、匿名作答、课堂观察 | 呈现教学怎样发生 |
| 研究资料 | 与课题直接相关的研究、教学案例 | 支持练习、反馈、操作或比较方法的设计 |
| 修改痕迹 | 原题、改题、追问语、课后记录 | 说明“实践”不是空泛感想 |

没有课堂数据时，论文只能如实写作“教学设计与实践思考”或“课例设计”，不能写成实验研究或显著提升。文献可以支持设计判断，不能替代未发生的课堂结果。

## 三、用技术路线图锁住论文骨架

技术路线图在写正文之前完成。它至少应有六类节点：

1. **共同目标**：学生学完后能做什么、说什么、解释什么。
2. **任务链**：按学习过程组织两到三层任务。
3. **设计审查**：检查目标、梯度、表达和材料是否匹配。
4. **课堂观察**：明确教师在现场看什么。
5. **判断节点**：任务是否真正支持共同目标。
6. **调整回路**：不能支持时怎样改题，支持时怎样进入下一次使用。

技术路线图必须与文章小标题一一对应。图中出现课堂观察，正文就必须有“观察什么、怎样追问”的具体段落或表格；图中出现调整，正文就必须写出至少一次原题到改题的变化。

## 四、按“问题—做法—观察—调整—回望”写正文

| 正文部分 | 应写的内容 | 避免写成什么 |
|---|---|---|
| 问题提出 | 一个具体课堂困惑、一句学生可能说的话、教师的追问 | 空泛的时代背景 |
| 教材转化 | 教材的学习路径怎样变成课堂任务 | 教材目录式介绍 |
| 具体做法 | 两到三组任务、题目、学具、同伴交流和教师语言 | 只有概念没有题目 |
| 课堂观察 | 学生可能出现的不同表现与即时追问 | 虚构成绩和比例 |
| 调整过程 | 哪一处练习为何改、改成什么 | “以后继续努力”式结尾 |
| 教学回望 | 本节课让教师重新理解了什么 | 夸大为普遍效果结论 |

每一节都遵循同一个写作动作：先给出一个可见的课堂事件或题目，再解释教师为什么这样设计，最后写清教师从中看到了什么和如何调整。

## 五、图表不是装饰

一篇 3 000—5 000 字教学实践论文，通常使用 3—5 张表和 2—3 幅图即可。图表数量要服务论证，不追求堆叠。

| 图表类型 | 最适合呈现什么 | 必须配套的正文说明 |
|---|---|---|
| 技术路线图 | 目标、任务、观察、调整之间的闭环 | 解释每个节点对应什么课堂动作 |
| 任务推进图 | 从操作到表达再到迁移的学习路径 | 说明学生在每一步要解决什么 |
| 课堂观察图 | 教师如何由表现进入追问与调整 | 说明“看见什么”以后怎样做 |
| 任务设计表 | 题目、意图、学生表现、教师处理 | 写出题目之间为何这样递进 |
| 追问表 | 常见表现与教师语言 | 说明追问如何帮助学生继续思考 |
| 调整表 | 原有安排、调整后安排、调整理由 | 写清修改依据，不只给出结果 |

图表前先用一两句提出问题，图表后必须用一个完整段落解释：**图表显示什么、为什么这样安排、教师怎样使用、它如何回应文章主问题。**

## 六、引用与参考文献

引用只服务于必要的判断。课标和教材说明内容定位；研究文献支持操作、比较解法、形成性反馈等做法。不要把参考文献写成资料清单，也不要为了显得学术而在每段塞引文。

提交前逐项确认：

- 正文中每一条参考文献至少被实际引用一次。
- 文献中没有把他人的课堂结果写成自己的课堂结果。
- 引用与本课的教学判断直接相关。
- 参考文献格式按比赛通知统一。

## 七、审稿门禁

### 内容门禁

- 标题是否足够小，能看到一个具体内容和教学动作？
- 文章是否围绕同一个问题推进，没有中途变成泛泛的理论综述？
- 是否给出了真实可执行的题目、追问或调整？
- 图表是否有图注、正文解释和明确用途？

### 风格门禁

- 开头是否从课堂困惑进入？
- 是否保留了教师思考的口吻？
- 是否删除了资料检索、数据库、版本核验、系统流程等后台语言？
- 是否删除了“显著提升”“全部掌握”等没有材料支撑的结论？

### 格式门禁

- 标题、内容提要、关键词、正文、参考文献是否齐全？
- 正文字数是否在通知范围内？
- 图表编号、图题、表题是否连续？
- Word、PDF 是否使用同一正文版本？

## 八、交付清单

每一篇论文至少生成：Markdown 正文、Word 版、PDF 版、技术路线图 PNG、审读记录和查重辅助资料。

## 九、本项目的标准流程

选定小切口 → 研读课标、教材和相关资料 → 形成资料包与课堂问题 → 先画技术路线图 → 写任务链、观察点与调整点 → 生成正文、表格和图件 → 逐图逐表补解释段 → 审稿（范围、引用、字数、格式） → 导出 Word、PDF 与 Obsidian 终稿。

这套流程的核心不是先写一篇很长的稿子再补图，而是让技术路线图先定义文章的逻辑，再让正文、表格和图件分别承担同一个论证任务。
