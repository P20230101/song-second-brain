# 文献“捕获与筑巢”（Search & Download）

## 文档用途

本页是从公开学术检索到本地 PDF 原件的最小可运行流程。它把检索结果固定为一份 `download_manifest.json`，再把 PDF 交给后续的摘要、证据链、引用和每日复盘流程。原始 PDF 只保存在本地 Raw sources，不自动发布到 GitHub Pages。

当前下载器位于 [`tools/literature_capture.py`](../tools/literature_capture.py)，使用 Python 3.12 标准库，不需要 API key。它会尝试 arXiv 和 Semantic Scholar；GPT Researcher 或人工筛选结果可通过 `--from-results` 接入。

本流程使用 arXiv 的公开 API；公开展示本项目时保留 arXiv 的数据使用致谢，并遵守其 API 使用条款。

## 输入参数

| 参数 | 填写内容 | 示例 |
| --- | --- | --- |
| 项目名称 | 本次文献集合的稳定名称 | `basis-bubble-dynamics` |
| 搜索主题 | 建议使用学术英语 | `dynamic relationship between basis and bubbles` |
| 关注重点 | 计量模型、实证方法、市场数据等 | 写在本页“本次任务记录” |
| 时间范围 | 可选起止年份 | `2020` 至今 |
| 筛选数量 | 最多保留多少篇 | `5` |
| 下载路径 | 相对于 Vault 根目录的 Raw 路径 | `raw/参考文献` |

## 执行顺序

1. 先在本页填写搜索主题、关注重点、时间范围和目标数量。
2. 在 Vault 根目录运行公开检索与下载：

   ```powershell
   python tools/literature_capture.py `
     --query "dynamic relationship between basis and bubbles" `
     --focus "计量模型、实证方法、市场数据" `
     --project "basis-bubble-dynamics" `
     --limit 5 `
     --year-from 2020
   ```

3. 检查 `raw/参考文献/<项目名称>/download_manifest.json`。每条记录包含标题、作者、年份、来源、原文链接、PDF 链接、本地文件名和状态。
4. 检查 `PDF原件/` 中的文件，再开始摘要和证据提取；不要把搜索摘要直接当作论文事实。
5. 把本次下载结果和待复盘问题写入[每日学习闭环](每日学习闭环-2026-09-10.md)，可复用结论再写回主题 Wiki。

## GPT Researcher / 人工结果接入

GPT Researcher 或人工筛选后，把结果保存为 JSON 数组，或保存为包含 `results` 数组的对象。每条记录至少需要 `title`；建议同时提供 `authors`、`year`、`source`、`source_url` 和 `pdf_url`：

```json
{
  "results": [
    {
      "title": "论文原始标题",
      "authors": ["Author A", "Author B"],
      "year": 2024,
      "source": "SSRN",
      "source_url": "https://ssrn.com/abstract/0000000",
      "pdf_url": "https://example.org/paper.pdf"
    }
  ]
}
```

然后运行：

```powershell
python tools/literature_capture.py `
  --from-results "C:\路径\results.json" `
  --project "basis-bubble-dynamics" `
  --limit 5
```

没有 `pdf_url` 的记录会保留在清单并标记为 `no-pdf-url`，不会凭空拼接下载地址。SSRN 等没有在本脚本中直接调用的来源，使用这个接口传入其公开 PDF 链接。

## 清单状态

- `downloaded`：本次成功保存 PDF。
- `exists`：目标文件已存在，本次未覆盖。
- `no-pdf-url`：找到文献但没有可确认的 PDF 地址。
- `error`：下载失败，清单中的 `error` 字段保留错误文本，便于稍后重试。

文件名由论文标题生成；同一项目再次运行会沿用已有清单中的文件名。脚本只创建或更新当前项目目录，不删除已有 PDF。
