# 阶段策略与范围护栏

## 总体目标

Math Agent 的长期目标是多 Agent 协作完成科研论文，但采用逐步升级方式。每个阶段只引入完成当前目标所需的 Agent，上一阶段的事实、状态和产物作为下一阶段的输入。

## 当前重点：文献研究引擎

当前只优先实现前期项目：

```text
研究主题/论文类型/目标期刊/研究方向
  ↓
检索候选文献
  ↓
获取并解析全文
  ↓
逐篇结构化研读
  ↓
建立文献卡片
  ↓
提取有原文定位的证据
  ↓
形成可供写作使用的证据库
```

当前阶段的验收重点不是生成长论文，而是回答三个问题：

1. 重要文献是否找全到足以支撑当前小题目。
2. 每篇纳入文献是否真的完成了主要章节的研读。
3. 每个可写论断是否都能回到原文片段和准确出处。

## 多 Agent 写作的渐进路线

### 阶段 A：文献研究引擎（当前）

启用 Literature Research Agent、Document Parser、Reading Agent、Evidence Agent 和 Citation Check 的最小能力。输出文献库、解析片段、文献卡片、证据矩阵和待核查清单。

### 阶段 B：总编辑与大纲

在证据门禁通过后，再启用 Supervisor/总编辑和 Outline Agent。总编辑只根据研究问题、目标期刊和证据矩阵制定大纲；大纲必须经过人工审核后才能进入写作阶段。

### 阶段 C：有限章节写作

先加入少量有明确边界的 Theory Agent、Method Agent 和 Result Agent。每个 Agent 只处理已经分配的章节和证据 ID，不负责改变研究问题，也不负责扩展文献范围。

### 阶段 D：审稿与定向修订

加入 Reviewer Agent、Citation Agent 和 Revision Agent。审稿意见定位到具体章节和段落，修订任务只修改对应问题，保留原版本。

### 阶段 E：图件与导出

最后接入 Figure Agent、摘要/标题/关键词生成和 DOCX/PDF 导出。只有通过证据、引用和人工终审的内容才能进入终稿。

## 防止 Agent 跑偏的四层控制

### 1. 项目宪章

每个项目有一份研究问题卡片，固定研究主题、研究对象、范围边界、论文类型、目标期刊和当前阶段。未经人工确认，Agent 不能修改研究问题或扩大范围；新的想法进入“待评估问题”，不直接进入正文。

### 2. 任务契约

总编辑分发的每个任务包含：任务目标、允许读取的资料、允许使用的 evidence_id、必须交付的字段、禁止完成的事项和验收条件。Agent 输出必须带回 `project_id`、`task_id`、`stage` 和引用的证据 ID。

### 3. 状态门禁

流程只能按规定状态前进：

```text
project_created
→ scope_locked
→ sources_collected
→ documents_parsed
→ literature_read
→ evidence_verified
→ outline_approved
→ sections_written
→ review_passed
→ final_approved
```

没有 `evidence_verified`，不能进入章节写作；没有 `outline_approved`，不能分发章节；没有 `review_passed`，不能生成终稿。

### 4. 越界隔离

Agent 发现超出当前研究问题的材料、结论或新方向时，写入 `deferred_queue`，记录来源和建议，不把它混入当前证据矩阵。无法核验的引用、缺失的数据和冲突的结论写入问题清单，由总编辑或人工节点处理。

## 总编辑的边界

总编辑是流程协调者和质量门负责人，不是事实来源。它可以拆解任务、决定先后、合并章节和发起修订，但不能替 Evidence Agent 修改原文含义，不能为 Result Agent 补造数据，也不能把未核验材料标记为已证实。

## 调度器的边界

调度器只根据任务类型、精度要求、上下文规模、来源风险和预算选择模型与推理档位。它不改变研究主题，不替 Agent 增加任务，不因某个 Agent 输出不足而自动扩大论文范围。任何升级都记录原因，便于回看整个项目是如何做出决定的。

## 当前实现取舍

先把“文献读得准、证据链完整、状态可恢复”做成稳定底座，再逐步接入写作角色。这样未来增加章节 Agent、审稿 Agent 或图件 Agent 时，它们共享同一份研究问题、证据矩阵和任务契约，整体方向不会因并行扩展而漂移。
