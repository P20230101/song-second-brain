## 当前崩溃根因（已定位）

Windows `.NET Runtime` 日志指向：

`VFM.FormMain.ClassVFMmain_OnSensitivityCalculated` → `NullReferenceException`。

对 19.2.2 内嵌程序集的只读检查表明，“灵敏度”按钮直接启动后台计算，没有先初始化 `InternalWork`、`ExternalWork` 和 Cauchy 应力矩阵；完成事件又无条件读取 `matSensitivity.Clone()`。对刚打开的工程，这些矩阵尚未由识别流程建立，因此会在完成事件崩溃。此问题不是照片数量、力帧名称或 `.dat` 文件损坏造成的。

## 不触发崩溃的固定顺序

1. 打开 `xy_0.2_whole_new.vfm`，确认数据帧和四条力序列可切换。
2. 在“材料/模型”中明确选择一个模型。PA12 起步先用“各向同性线弹性”，只勾选需要识别的参数（例如 `E`），泊松比先固定；不要让识别参数列表为空。
3. 先点击“开始识别/Identification”，让程序完成应变计算和识别初始化；等待进度结束并确认出现应变或识别结果。
4. 识别初始化完成后，再进入“灵敏度/Sensitivity”并计算。不要在刚打开工程、未完成第 3 步时直接点击灵敏度。
5. 首次成功后另存为新文件，例如 `xy_0.2_whole_线弹性初始化.vfm`，不要覆盖修复母版。

如果第 3 步也失败，先把载荷范围缩短到首帧—峰值附近的 2–10 个连续帧，网格设为 5×5 或 9×9，确认最小流程跑通后再扩大到全 258 帧。

## 2026-09-13 纯弹性结果判读

当前工程已经成功完成一次各向同性线弹性识别，但截图中的结果不能作为材料参数：

- `E = -1.824×10^4 MPa`（负刚度）；
- `ν = 0.9418`（超出稳定各向同性材料的物理范围）；
- `Q11 = -1.615×10^5 MPa`、`Q12 = -1.521×10^5 MPa`；
- 结果内部满足 `Q11 = E/(1−ν²)`、`Q12 = νQ11`，说明软件只是对当前输入做了数学拟合，并不代表拟合物理有效；
- `LoadLimit=0;257`，包含全程 258 帧；力在 `Img000237.jpg` 附近达到约 1.6 kN，`Img000238.jpg` 突然降到约 12.5 N，后续是破坏/卸载段，不能用于纯弹性拟合；
- 当前工程标记为 `is2D=True`，这是二维平面 VFM 工程，不是立体 DIC 数据。

第一次排查应这样重跑：

1. 将载荷范围暂设为首帧后的连续早期帧（例如 5–80，仅用于排查，不作为最终弹性区间）；
2. 确认拉伸边界的外力方向与试验坐标一致，使拉伸功为正；不要无依据地把四条力全部取反；
3. 力保持为 N、长度保持为 mm、厚度填写实测值，当前工程的像素换算为 `0.09982 mm/pixel`；
4. 若 `E` 仍为负，先修正边界力角度/法向方向；若符号正确但数量级仍远大于 PA12，检查 N 与 kN、厚度和边界宽度是否混用；
5. 只有在 `E>0`、`ν` 落在合理范围且应力—应变曲线只覆盖起始线性段后，才保存为候选纯弹性参数。峰值前和断裂后的帧另行用于塑性/破坏分析。

## 打开步骤

1. 先关闭当前 MatchID 的 VFM 子窗口，保留原始数据目录不动。
2. 在 MatchID 2019 的 VFM 模块中选择“打开项目”，打开 `xy_0.2_whole_new.vfm`。
3. 先查看载荷帧是否能切换，再按“材料模型 → 开始识别 → 等待完成 → 灵敏度”的顺序操作。
4. 只有当载荷曲线、位移场和灵敏度结果均出现后，才保存为新的项目文件；不要覆盖原文件。

## 验收标准

- 项目能打开且不回到空白窗口；
- 10 个载荷帧均可切换；
- 四条边界力序列均显示数值；
- 灵敏度计算完成后能显示结果；
- 能导出至少一个应力/应变或参数结果文件。

## 已知限制

该修复只处理工程内的无效力帧名和点数不一致问题，不改变设备参数、相机参数、DIC 算法或原始 `.dat` 数据。19.2.2 的灵敏度回调没有空值保护；若严格完成上述初始化顺序后仍崩溃，应停止在该按钮上反复尝试，改用许可证允许的更新版本或联系 MatchID 技术支持。与此同时，可以用外部 VFM 脚本对已导出的 DIC 应变场和同步力做识别，不影响论文推进。
